# web/ — the dashboard

`drowse/web/` is the Python half of the dashboard: `routes.py` mounts the committed bundle in
`dist/`; `__init__.py` re-exports `register_web_routes` and `dist_path`. The Svelte 5 + Vite
source is `webui/` at the repo root (covered here; no AGENTS.md of its own). Routes, WS frames
and auth are in `drowse/server/AGENTS.md`.

## Mount (`routes.py`)

`create_app(..., web=True)` registers the mount after every API route so its catch-all cannot
shadow `/v1/*`, `/api/*` or `/drowse/v1/*`. `drowse serve` mounts by default (`--no-web` opts
out); `create_app` defaults to `web=False`. Mount once per app (a second adds shadowed
duplicates).

- `/assets` is a `StaticFiles` mount; `GET /` serves `index.html`. The catch-all `GET
  /{full_path:path}` 404s `api`, `v1`, `drowse` and anything under them, serves top-level dist
  files from an allowlist built at mount time, 404s a path whose last segment is a dotfile or
  has a static-file extension but is not in dist (so a browser's `/apple-touch-icon.png` never
  reads the shell; a bipolar concept's dotted name is still a route), and otherwise falls back
  to `index.html`. `full_path` is only a dict key, so `..` traversal is impossible.
- Only split JS chunks are content-hashed; `assets/drowse.js` and CSS/font/JSON assets keep
  fixed names, so every dashboard response sends `Cache-Control: no-cache` (revalidate by ETag;
  heuristic freshness would run an old dashboard against an upgraded server). A missing
  `dist/index.html` raises `WebUINotBuilt` (500).
- The shell is public and holds no data. The CSP's `script-src 'self'` bans inline scripts, so
  the theme bootstrap is the separate `/theme-preflight.js` (Ledger's pre-paint script, served
  by `vite.config.ts` in dev and written into the build from `@stdlogits/ledger`; `index.html`
  loads it with `data-ledger-theme-key="drowse.theme"`). `connect-src` allows self,
  `https://www.neuronpedia.org` (SAE descriptions) and `https://drowse.ai/api/contact`; any other
  third-party fetch needs a CSP entry.

## Build and the committed bundle

```bash
cd webui && npm ci   # Node 24.x
npm run dev          # :5173, proxies /drowse (incl. WS), /v1, /api to :8000
npm run check        # svelte-check, check-theme, check-runtime-boundary, node suites
npm run build        # vite build into ../drowse/web/dist + check-build-isolation
```

- `drowse/web/dist/` is committed and is what wheel users run; commit a rebuild with any change
  to `webui/src`, `public`, `index.html`, `vite.config.ts`, `scripts/dashboard-assets.mjs` or
  npm deps. CI runs `npm ci`, `check`, `build`, then fails on any `git status` entry under
  `dist/`. `emptyOutDir` wipes `dist/` each build.
- `webui/public/` holds the brand set (the closed eye on Ledger's depth ramp): the two
  `drowse-mark-*.svg`, `favicon.svg`, committed rasters drawn from it (`favicon.ico`,
  `icons/*`) and `social/drowse.png` (drawn by `node scripts/social-card.mjs`). drowse.ai copies
  the set. `scripts/dashboard-assets.mjs::shipsInDashboard` keeps `social/`, `icons/` and
  `favicon.svg` out of the dashboard; `scripts/check-build-isolation.mjs` fails the build on
  hosted leaks (`sw.js`, manifest, `_headers`, wasm, MLC/WebLLM files, a PWA bootstrap).
- `lib/data/sae-descriptions/` ships as `assets/gemma-3-{270m,1b,4b}-it.json` to label local
  SAELens gemma-scope-2 releases offline (`node scripts/build-sae-descriptions.mjs`).
- Node suites (`webui/scripts/*.test.mjs`) load modules through Vite SSR with a stub
  `installRuntimeClient`; `saeDescriptions.ts` and `tokens.ts` are also imported by plain Node
  (here and in drowse.ai), so they take no extensionless value imports. The mount is covered by
  `tests/web/test_web.py`.

## Generated REST types (`lib/types.gen.ts`)

Generated by `scripts/generate_webui_types.py` from `create_app(MagicMock())`: TS for the
**response** schemas of every `/drowse/v1/*` route and what they reference. To change a
response, edit its TypedDict (`server/response_models.py`, or `readout/measurements.py` for the
envelope) and rerun; `--check` diffs (CI; `tests/invariants/test_webui_types_parity.py` also
requires a declared response schema on every non-streaming native route and kebab-case paths).
In a worktree run it with `PYTHONPATH=.` (it imports `drowse` from the environment).
`SCHEMA_RENAMES` maps engine names to dashboard names; `PROPERTY_OVERRIDES` types the opaque
payloads (loom token rows, fit diagnostics, manifold domains). `lib/types.ts` is hand-written
(requests, WS/SSE frames, client types), re-exports the generated file and is the only importer
of it: request drift is a loud 400 (`extra="forbid"`), response drift would be silent, hence
generated.

## Talking to the server

- The client uses the literal session id `default`; `lib/api.ts` covers only routes the
  dashboard calls.
- The API key lives in memory (`lib/runtime/http-auth.ts`), read once from `<meta
  name="api-key">` if an embedding page supplies one, else set via `setApiKey` from the
  API-access drawer. HTTP sends `Authorization: Bearer`; the WebSocket offers `drowse.v1` and
  `drowse.auth.<base64url-utf8-key>`.
- WS `/drowse/v1/sessions/default/stream`: `submit` is the composer's one door (authored and
  generated roles independent; `generated_role: null` appends without generating; `text: null`
  continues from the selected leaf); `generate` covers continuation, explicit message replay
  (the A/B shadow), the token fork and `generate_seat`; `stop`. The A/B comparison sends only
  the composer's observation knobs (`sampling.svelte.ts::buildObservationSampling`) so a call
  field never outranks the compared turn's own.
- On `resync` (frames dropped for a slow reader; generation continued into the tree)
  `stores/ws.svelte.ts` holds later frames and reads the tree through the same recovery barrier
  as a revision gap, and `loom.svelte.ts::catchUpStreamingRows` appends the streaming node's
  rows past the last live `raw_index`. The status line's rate and time are `done.result.
  tok_per_sec`/`elapsed`, not frame arrivals. An unexpected close reports the channel `closed`
  with `code: "RUNTIME_CONNECTION_LOST"` and reconnects. The shared types also carry
  browser-runtime extensions Python never emits or accepts (the `generation_progress` frame,
  `position_spans`/`position_indices`).
- Error frames' `code` is the exception class name; render with `describeError(e)`
  (`lib/runtime/errors.ts`).

**Measurements.** The read side is one versioned envelope (`readout/measurements.py`): scope
`"token"` on each `token` frame (whole), `"aggregate"` on `done.result.measurements`,
`"replay"` (`provenance: "replayed"`) from `.../instruments/{family}/token-readout` and the
token anatomy. A loom token row keeps only what the tint, the rack trace and the tree filter
read (`token_row_measurements`: `scores` plus each geometry reading's `fraction` and `coords`;
`TokenRowMeasurementsJSON`); everything else (geometry summaries and layers, lens, SAE and unit
readings, chips, features) is replayed through `runtime/tokenReadoutCache.ts` (keyed,
deduplicated) so it survives refresh and save/load. The reply's settled reading rides the node
(`aggregate_measurements`). A geometry replay carries `subspace_coords_per_layer`, which the
Probes room uses to place a token in a manifold plot.

A captured prompt (authored) row is the same projection replayed through the node's
`prompt_capture`: `TokenScore.promptIndex` (thinking rows first, `lib/tokenRows.ts::
authoredRowIndex`), replayed at `replayIndex(token)` (`rawIndex ?? promptIndex`) under
`drawers/token/readings.ts::replayAnchor`; it has no `rawIndex`, so it never forks.

`mergedReadings` folds the three families' readings into one name-keyed map; branch on the
reading's shape (`isScalarReading`: has `value` means lens or SAE; else `ProbeReadingJSON`).
`SessionInfo.instruments` is the only instrument-state representation. A steered view keeps the
row's values and replays the rest; a steered replay the server refuses (422, only a
thinking-phase window on a thinking family) sets `ReplayReadout.refused` and the drawer
switches to Unsteered once per node. Replayed values are never written back as captured.

## The drowse.ai seam

drowse.ai ([stdlogits/drowse.ai](https://github.com/stdlogits/drowse.ai)) pins this repo as a
submodule and builds `webui/src` with a WebGPU runtime in place of the HTTP client, through the
`RuntimeClient` contract and the `@runtime-*` aliases. Its Vite config imports
`webui/vite.config.ts` (default export is a function of the command). It computes parity
(grammar, `compose_call`, sampler, lowering, fit) from the pinned Python; a semantic change here
reaches it with its next pin bump.

What it imports or reads is the interface: shared modules by path (the stores barrel,
`lib/types.ts`, `lib/runtime/{contracts,registry,services}.ts`, `lib/theme.ts`,
`lib/brandMigration.ts`, `lib/ui/*`) plus component source text and CSS class names its tests
read. Grep drowse.ai's `webui/{src,hosted,scripts,e2e}`, `browser-runtime/` and `tests/` before
moving any of them. Its tests regex-parse the `DRAWERS` rows (`  name: {`) and pin their count.

**RuntimeClient** (`lib/runtime/contracts.ts`): `mode` (`http` | `browser` | `fake`); services
`sessions`, `profiles`, `probes`, `manifolds`, `templates`, `tree`, `instruments`; an `events`
channel whose `closed` state may carry `code` (`RUNTIME_CHANNEL_CLOSED`, default, or
`RUNTIME_CONNECTION_LOST`, HTTP only); `dispose()`. `RUNTIME_SERVICE_METHODS` is
compile-checked. Members a runtime may lack are optional with an entry there and a UI check:
`instruments.tokenAnatomy?` / `unitActivity?` (`replayCapabilities`), the unit reads
(`unitReadsAvailable`) and `unitLabels?`. Where `tokenAnatomy` is absent the token view and
Lens room fall back to the lens readout (`LensReading.svelte`, `lib/lensRoom.ts::
readoutLayers`).

`main.ts` installs `HttpRuntimeClient` into `runtime/registry.ts` before importing `App`; the
registry refuses a second runtime (drowse.ai also installs `RuntimeCapabilities` and a
`HostedController`). Shared code reaches the runtime only via `runtimeClient` or
`runtime/services.ts`; `check-runtime-boundary.mjs` (AST-based) fails if anything but
`runtime/http-client.ts` imports `lib/api.ts`. `DRAWER_REQUIREMENTS`
(`runtime/ui-capabilities.ts`) gates drawers on capability operations (none installed means
all available).

**Aliases** (declared in both `vite.config.ts` and `tsconfig.json`, only where the builds need
different components at one import site):

| alias | here | drowse.ai |
|---|---|---|
| `@runtime-jlens-source` | `panels/JLensSourceSection.svelte` | `src/hosted/ui/JLensSourceSection.svelte` |
| `@runtime-sae-source` | `panels/SaeSourceSection.svelte` | `src/hosted/ui/SaeSourceSection.svelte` |
| `@runtime-jlens-missing` | `drawers/token/JLensMissingState.svelte` | `src/hosted/ui/JLensMissingState.svelte` |
| `@runtime-session-drawer` | `drawers/SessionAdminDrawer.svelte` | this repo's `UnavailableRuntimeDrawer.svelte` |
| `@runtime-local-drawer` | `drawers/UnavailableRuntimeDrawer.svelte` | `src/drawers/LocalRuntimeDrawer.svelte` |

drowse.ai's lens section renders `panels/rooms/lens/LensQuad.svelte` by path without `column`,
keeping the local fit (`LensFit`) out of its bundle (`scripts/lens-room.test.mjs`).

Hosted-only code (WebGPU runtime and workers, catalog and downloads, PWA, hosted shell and
onboarding, its own steering parser and archive mirror) lives in drowse.ai's
`webui/src/hosted/`; this tree takes no WebGPU, MLC or worker imports. Hosted residue here that
should not grow: `lib/shell.ts`, `lib/homeController.ts`, `lib/webmcp/{hostedTools,homeTools}.ts`,
`runtime/gpuRecovery.ts`, the catalog/download/worker half of `runtime/contracts.ts`, the
hosted session store in `lib/sessionPersistence.ts`. `lib/brandMigration.ts` stays: drowse.ai
users hold browser data under the earlier names `polythetic` and `saklas` (localStorage,
IndexedDB, OPFS, fields like `saklas_version`); it migrates opportunistically, and
`lib/theme.ts`, `lib/chatBackup.ts` and `runtime/localData.ts` recognize the old names too.

## State

`lib/stores/` holds one `$state` slice per concern; the barrel re-exports the slices that
stream, loom, chat and instruments share, others (`selection`, `rooms`, `workbench`,
`manifoldJobs`, `preparations`, ...) are imported directly. Slices import each other directly;
the graph has cycles (loom <-> ws, chat <-> pending) that are safe only because every
cross-slice reference sits in a function body. `$state` does not track `Map.set`, `Set.add` or
writes inside stored objects: shared collections are `SvelteMap`/`SvelteSet` and mutators
replace the value (`entries.set(name, { ...e, coords })`); an in-place `entry.current = v` on
the per-token probe path would freeze every sparkline. `createPreparationSlice` builds the four
background jobs (lens `fetch`/`fit`, SAE `fetch`/`train`) on one poll loop; a family's two
operations share one server resource, so `check()` resumes only its own.

- **Rooms** (`rooms.svelte.ts`, route `#/lens`, `#/artifacts/packs`): Workbench, Units, Lens,
  Probes, Artifacts, Model. Units, Lens, Probes read the conversation; Artifacts is where what
  they read with is fitted, fetched, built and installed, and every setup link goes to its
  section (`goto("artifacts", "lenses")`). A `ROOM_SECTIONS` entry is a hosted drawer or, with
  `drawer: null`, a panel the room draws from the `panels` map it gives `RoomSections`;
  `sectionShown` says which sections this runtime has. Section values are unique across rooms
  and each has a `does` line the palette lists. On a phone the header tabs become the menu's
  Rooms and the shell draws the crumb.
- **Selection** (`selection.svelte.ts`): what the Inspector shows (none, token, probe, unit),
  `tokenRest`, and `termOpen`. `workbench.svelte.ts`: what the Page shows, the phone sheet,
  the "+ Steer" picker kind (`openSteerPicker`).
- **Token cursor** (`tokenCursor.svelte.ts` over `drawers/token/cursor.ts`): one position over
  the conversation's tokens (each turn's thinking then text, prompt turns at their captured
  rows) or the whole reply; it is the workbench's token selection (a probe or unit selection
  leaves it at `tokenRest`; moving it selects with `{ step: true }`). A position holds while its
  turn holds the node it was made on (`loom.svelte.ts::syncChatLogFromTree` calls
  `reconcileTokenSelection()`). `TokenStrip` draws it atop the readout rooms; rooms replay only
  once it has rested (`settled`, 140 ms).
- **Layouts**: from 1240 px Thread | Page | Inspector; down to phone, Page | Inspector with the
  thread folded into a row; phone (720 px wide or less, or 520 px tall or less; one shared
  query across App, `drowse.css`, Chat, RawBuffer, LoomSidebar) is one column with the Inspector
  as a sheet. The thread shows the active path then, dimmed, the turns below the active node
  along the last-visited path (`lib/threadPath.ts`). `ConversationFormat` (`genUiMode`, per
  model, not a sampling field) is absent on a base model.
- **Readout rooms** set nothing up; a missing catalog, lens or probe is one link to Artifacts.
  Units reads `unitActivity(node, { top: 1024, rawIndex })` (atlas, unit summary with trace and
  Push/Silence); Lens replays the token anatomy (`{ k: 8, units: 1, patterns: 0 }`) layer by
  layer through both lenses (each faded by its depth weight, crossover band washed) with a
  Steered | Unsteered switch, and whole reads `aggregate_measurements`; Probes lists flat
  probes, manifolds (`ProbeGeometryPlot`) and pinned SAE features. Only Lens replays without
  the steering; Units and Probes read as generated.
- **Artifacts room** order: `units` (neuron-lens catalog), `lenses`, probe tools (`build`,
  `packs`, `combine`, `templates`, `roles`), `saes`. The `lenses` 2x2 (`LensQuad` in the
  `@runtime-jlens-source` section) holds the S and R families with their selected source at
  out and mid, sources and a local fit seeded from the server's `fit_documents`. A source the
  server marks not `compatible` says it is not loaded; a failed fit offers Replace only when
  `replaceable`. The room's fit always covers every layer. **Model room** (`#/model`): facts
  (layers, neurons and heads from session info's optional `architecture`, device, versions,
  depth ramp), what is prepared (catalog, lenses, SAE) with links, then health/local runtime
  and API access tabs.

## Drawers

`drawers/index.ts::DRAWERS: Record<DrawerName, DrawerEntry>`: each row has a lazy `load()`
(rendered by `DrawerOutlet`, cached), optional `params` (one `RackDrawer` serves `subspace` and
`manifolds`), `narrow`, and either a `launcher` or `launcher: null` with a `via` string.
`RAIL_CATEGORIES` derives from launchers. `openDrawer(name, params)`
(`lib/stores/drawers.svelte.ts`) is the one entry point: `token_drilldown` and
`probe_inspector` are Inspector selections; tools a room hosts (`ROOM_SECTIONS`) go to their
room section; everything else is a dialog over the page (header, notices and rooms host inert,
Tab trapped, `out:` transitions run inert; focus returns to the opener while still a tab stop,
else the header Menu: `lib/focusTrap.ts::returnFocus`).

To add a drawer: add its name to `DrawerName` in `lib/types.ts`, then one row each in `DRAWERS`,
`DRAWER_REQUIREMENTS` and `lib/webmcp/catalogue.ts::INTERFACE_CATALOGUE` (all
`Record<DrawerName, ...>`, compiler-enforced); this changes drowse.ai's pinned count. A new
runtime service method needs a `RUNTIME_SERVICE_CATALOGUE` entry there.

## Surface invariants

- **Expression.** `lib/expression.ts` only serializes; the server grammar is the only parser.
  Order: subspace terms (shared `subspaceAlong`), projections (`α base~onto` / `α base|onto`),
  `jlens/`/`slens/` atoms, `sae/` atoms, units (`neuron/...` pushed or silenced, `head/...`
  only silenced), manifold terms (own `along[,onto]`). Timing is `trigger` (five presets, or
  `FIRST_N`/`AFTER_N` with `tokens`) plus `gate` (probe key, comparison, threshold);
  `triggerClause` writes it as `_trigger_name` does. A term's `layers` is its `{...}` clause
  (`lib/steering/layers.ts` mirrors `format_layer_indices`); a unit carries its layer and writes
  none. `Variant` tracks the grammar (`raw`, `sae`, `sae-*`, `role`, `role-*`, `from`,
  `from-*`). Chips write the canonical form: `!x` at full strength, `-!x` at -1, `0.5 !x`
  otherwise (`formatBang`); numbers as Python `%g` (`formatCoeff`).
  `tests/fixtures/recipe_chips.json` pins both directions (`tests/web/test_recipe_chips.py`,
  `scripts/recipe-chips.test.mjs`).
- **Recipes are chips, not text.** A recipe from elsewhere (WebMCP `drowse_set_steering`, a
  saved conversation, the CLI `-S` default) goes through `applyRecipe`: `POST
  .../steering/validate` returns each term's `parts` and `lib/steering/recipe.ts::
  recipeAsChips` makes chips when every term fits exactly; otherwise it stays one read-only
  chip (`steerRack.readOnlyRecipe`, sent as written; a chip added afterwards replaces it;
  `recipeTicket` stops a late check overwriting a newer rack). Agent-only (no chip): flat terms
  at different strengths, a unit removal below zero, a selector naming no installed manifold,
  the same selector twice, a strength past the dial. Chips hold but the editor does not write:
  gates on any channel but a probe's main reading, a gate on the Prompt window (never fires), a
  projection whose base is not a raw one- or two-node flat concept.
- **Rack families.** `fitKind.ts::fitGeometry` (`resolved_fit_mode ?? fit_mode`): `pca`/`baked`
  is subspace, `spectral`/`authored` manifold, unfitted `auto` unresolved. Subspace terms share
  one `subspaceAlong` (the composer merges them into one affine subspace). Lens token atoms
  (`jlens/<word>` toward saying it, `slens/<word>` toward having read it, one "As said | As
  read" pair) and SAE atoms carry their own alpha (`ATOM_DEFAULT_ALPHA = 0.3`; a single
  token/feature direction runs hotter than a concept vector and 0.5 or more over-steers into
  repetition). A unit term (`mode: "unit"`, keyed by the full reference) is one per unit: a
  neuron pushed (`UNIT_PUSH_ALPHA` 3, to +/-`UNIT_PUSH_MAX` 8, larger than an atom because it
  acts at one layer) or a neuron/head ablated (`!...`, `UNIT_ABLATE_ALPHA` 1; `0.5 !...`
  blends); a head has no push. Switching operation takes that operation's own alpha
  (`setUnitOperation`). `unitTerms.ts::unitTermProblem` refuses a negative ablation alpha and a
  head push in `setUnitTerm` (the one unit mutator), `patchSteerEntry`, the snapshot validator
  and WebMCP rack edits; units never take a `{...}` clause.
- **Units.** The unit view and Units room read through `lib/stores/units.svelte.ts` (getters in
  `$derived`, `request*` from `$effect`, nothing asked while a generation runs) and hide where
  `unitReadsAvailable` is false. A neuron reads the side that fired here (`peakPole`); heads
  rank by their own write (`rankHeads`), not against neuron peaks. Unit probes are the `units`
  family (`UnitProbeCard`) and merge via `mergedReadings`.
- **Templates.** `validateTemplateDraft` mirrors `drowse/store/templates.py` rule for rule;
  change both together.
- **Pending queue.** A submit during a generation or behind queued items is deferred. Rack
  mutations go through `enqueueOrApply` (coalesced under `coalesceKey` `"rack"`); the queue
  drains FIFO, one item per WS `done`/`error`. In `RawBuffer` an edit forks a branch at the
  first changed character (`resolveDivergence`) instead of overwriting.
- **Persistence.** The server loom tree is authoritative and is never first-painted from a
  browser cache (node ids go stale on restart). `ConversationSnapshotV8` backs the IndexedDB
  library (`ConversationAutosave`, only while no generation runs) and backup files
  (`lib/chatBackup.ts`). localStorage holds presentation preferences only
  (`safeLocalStorage*`).
- **Steering in one place.** Every term is made through `steerActions.ts` and lands as a chip
  with its editor open (`openTermEditor`); only the chip's Remove takes a term out. "+ Steer"
  (`panels/rack/SteerPicker.svelte`) offers kinds in one priority order (neurons and heads, lens
  tokens, flat concepts, manifold positions, SAE features; a runtime without units omits the
  first; a missing lens or SAE is a link to Artifacts); the chips sort by that order
  (`RecipeBar`'s `ORDER`). A unit's term queues behind a running reply like any rack edit
  (`pending.svelte.ts::rackEditQueued`).
- **Term editor** (`panels/rack/TermEditor.svelte`): strength dial ranges
  (`terms.ts::strengthDial`): flat and projection terms -2 to 2, atoms -1 to 1, curved terms 0 to
  1 (composition refuses a negative curved along), unit removal 0 to 1. A probe gate
  (`terms.ts::gateProbeKey`) never reads the prompt, so adding one moves Always/Prompt to
  Response. Relating a flat concept (Along/Not along another) re-keys the chip as a projection
  (`relateSteerEntry`; node 0 is `+`). Where a term acts comes from `POST
  .../steering/validate` (`terms`, `n_layers`), asked once per term text at strength 1 and
  `@response` so a probe never drops the cached prefix (`termLayers.svelte.ts`; re-asked after
  a moved position rests, `SETTLE_MS`); a runtime that reports none hides the strip.
